# Release Checklist

Run for every release, alongside docs/release-plan.md. Phase 4 of the
release plan executes this list.

## How to read this list

Ticks below were set for v1.0.4 and say how each was checked. Items
that need a real API key, a real display, or a person clicking through
the installer stay unticked on purpose. An unticked item is honest; a
ticked one with no evidence is not. Section "Known gaps" lists the
items that the test suite does not cover, so a tick here is never
mistaken for coverage.

## Known gaps

These shipped before v1.0.4 and are recorded here so a tick above is
not read as coverage. Details and the fix list are in
code-review-2026-09.md.

- Auto refresh, the single-instance lock, and the crash hooks have no
  tests at all. `main.py` and `crash_hooks.py` are both at 0 percent
  coverage, and both are release-plan items marked complete.
- The startup path that restores the cached weather is untested.
- The leak guard can only see ERROR records, because the fixture never
  lowers the logger level from its default of WARNING.
- `test_contrast.py` hand-copies its colors instead of reading them
  from `console.qss`, so a change to the stylesheet would not fail it.
- There is no continuous integration, so nothing on this list is
  checked automatically between releases.
